# Customer Details and Shopify orders

The ticket header has a visible **Details** button that opens the customer panel. The panel combines the ticket contact and support history with a protected Shopify customer lookup. It scrolls within the available height; compact windows and phones use the existing accessible modal sheet with Escape dismissal and focus restoration.

For a verified email sender, Shopify details include name, email, phone, location, customer-since date, order count and lifetime spend in Shopify's currency. The matched order opens automatically. Recent orders can be expanded to show products, variant/size, SKU, quantity, product images, original unit prices, discounted item totals, order subtotal, discounts, shipping, tax, total, refund amount, tracking and recent refund history. A missing or failed product image displays an explicit placeholder; missing prices and currencies remain unavailable.

The first lookup previews five products on each of up to ten recent orders, plus an older order matched to the ticket. **Load remaining products** fetches additional pages for large orders, with ownership checked on every page. Extremely large orders retain an explicit partial-results notice. Staff can look up another order number using the existing ticket-scoped orders API. The connection's permissions determine whether older orders are available. Shipment and refund history retain the existing bounded recent records; the refunded total now comes from Shopify's order-level total.

Read-only access and isolation remain enforced by `lib/store.ts`: only the verified sender's own customer and orders are available, every store/order endpoint requires staff authentication, and simulator/CLI credentials cannot read store data. Simulated identities have no Shopify records; the panel explains this. Changing tickets clears the previous customer's panel and ignores late responses. Background store failures retain the last successful snapshot with a visible warning and timestamp; staff can refresh or retry.

The added order fields use Shopify Admin API 2026-10. The customer query, order-number query and paginated product query were validated with the Shopify skill's schema validator. Field semantics were checked against Shopify's [LineItem](https://shopify.dev/docs/api/admin-graphql/2026-10/objects/LineItem) and [Order](https://shopify.dev/docs/api/admin-graphql/2026-10/objects/Order) references. Item totals include line/code discounts; order-level discounts are reflected in the separate order total. All store tests use mocked Shopify responses and browser tests use scratch data with external credentials disabled.

Validation: the complete `npm run verify` gate passed with secret scanning, lint, typecheck, 168 unit/route/safety tests, 58 QA scenarios with zero misses, the production build and 28 Playwright browser tests. New safety checks cover image/variant/price mapping, missing and unsafe image URLs, complete order refund totals, and ownership verification on each additional product page. Browser checks cover desktop and phone Details, expanding older orders, image placeholders, retry/stale data, late responses after ticket switching, named-order lookup, and remaining-product loading. Desktop and phone screenshots were inspected. The additional browser suites use separate scratch client addresses so the real login rate limit remains unchanged.

Public login/health/readiness checks return 200; signed-out customer-store and order API requests return 401. The six Details browser tests also passed after correcting the synthetic fixture totals to balance.
